# المعمارية

## 1. اختيار النموذج الأساسي: Qwen3

| المعيار | Qwen3 |
|---|---|
| الترخيص | Apache 2.0، يسمح بالاستخدام التجاري والتعديل والنشر |
| العربية | مدرّب على 119 لغة، والعربية منها، وأداؤه جيد بالعربية والبرمجة |
| الأحجام | 0.6B، 1.7B، 4B، 8B، 14B، 32B، **وكلها بنفس الـ Tokenizer** |
| الأدوات | دعم كامل في transformers وpeft وvLLM وOllama وllama.cpp |

**أهم نقطة للتوسع:** كل أحجام Qwen3 تستخدم نفس الـ Tokenizer. معناها البيانات التي ترمّزها اليوم لنموذج 1.7B تصلح كما هي لنموذج 8B أو 14B لاحقًا، بدون إعادة معالجة مليارات التوكنات. الكود يتحقق من هذا تلقائيًا في `same_tokenizer`.

| المرحلة | النموذج | GPU المطلوب (QLoRA) |
|---|---|---|
| البداية (مجاني) | `Qwen/Qwen3-1.7B` | T4 بذاكرة 16GB (Colab/Kaggle) |
| تحسين | `Qwen/Qwen3-4B` | 16–24GB |
| إنتاج | `Qwen/Qwen3-8B` | 24GB (A10/L4/4090) |
| متقدم | `Qwen/Qwen3-14B` / `32B` | 40–80GB أو عدة GPUs |

تغيير النموذج يكون بسطر واحد في `config/default.yaml` (`model.base`).

**بدائل** تصلح بنفس الكود: `ALLaM` (عربي، من SDAIA)، و`Jais` (عربي)، و`Llama 3.x`، و`Gemma 3`. هذه البدائل لها Tokenizer مختلف، فتحتاج `retokenize` مرة واحدة. الملفات الأصلية محفوظة لهذا الغرض.

**لماذا لا نبني Transformer من الصفر؟** تدريب نموذج بمستوى مفيد من الصفر يحتاج تريليونات التوكنات وآلاف ساعات GPU. أما 500M إلى 5B توكن فهي كمية ممتازة لـ **التدريب المستمر (continued pretraining) والتخصيص** فوق نموذج قوي، وهذا ما يفعله المشروع.

## 2. خط البيانات

```
ملف ─► قارئ متدفق ─► تنظيف ─► كشف التالف ─► إزالة التكرار ─► تقسيم train/eval ─► ترميز دفعات ─► شاردات
       (سطر/سجل)     NFC،      طول، نسبة      بصمة blake2b      حتمي حسب            256 مستند       uint32
                     رموز،     الحروف،        في SQLite         البصمة (0.5%)       لكل دفعة        memmap
                     تكرار     تكرار الأسطر    على القرص
```

- **الذاكرة ثابتة** مهما كبر الملف: الملفات تُقرأ سطرًا بسطر (و`ijson` لملفات JSON الضخمة)، والتوكنات تُكتب للقرص كل مليون توكن.
- **إزالة التكرار** تتم عبر جدول SQLite بمفتاح 16 بايت. يتحمل مئات الملايين من المستندات، ويعمل عبر كل الدفعات، فالمستند المكرر في ملف جديد يُرفض أيضًا.
- **فشل المعالجة لا يترك أثرًا:** الشاردات الجزئية تُحذف، وبصمات التكرار تُلغى (rollback)، والسجل لا يتغير.
- **الشاردات** حجمها 50M توكن (حوالي 200MB). مليار توكن يساوي حوالي 20 شارد، و5 مليار يساوي حوالي 100 شارد، والبنية نفسها لا تتغير.

## 3. الإصدارات

```
Dataset:  v1 = [s1 s2]          v2 = [s1 s2 s3]          v3 = [s1 s2 s3 s4 s5]
                    │                     │                         │
Model:   base ──► v1 ──(بيانات أحدث)──► v1.1 ──────────────────► v1.2
                                          └──(--bump major)──► v2
```

- **الشاردات لا تُعدّل أبدًا.** الإصدار الجديد هو قائمة شاردات تبدأ بشاردات الإصدار السابق، فلا يتكرر أي شيء على القرص.
- كل إصدار نموذج يسجّل النموذج الأساسي، والأب، وإصدار الداتاسيت بالضبط، وعملية التدريب، والإعدادات، ونتائج التقييم. يُحفظ هذا في `model_card.json`.
- كل إصدار يحمل Adapter تراكميًا، أي أن مواصلة التدريب تكمل على Adapter الأب. لهذا يكفي `base + adapter(vX)` لتشغيل أي إصدار.

## 4. التدريب

- **QLoRA (افتراضي):** النموذج بدقة 4-bit NF4، والـ LoRA على كل الطبقات الخطية، ومحسّن `paged_adamw_8bit`.
- **Mixed precision:** bf16 إذا كان الـ GPU يدعمه، وإلا fp16.
- **Gradient checkpointing وGradient accumulation:** للوصول لـ batch فعّال كبير على GPU صغير.
- **Packing:** النصوص تُدمج في كتل بطول السياق بالضبط، فلا يضيع حساب على الحشو (padding).
- **Multi-GPU:** يعمل عبر `torchrun --nproc_per_node=N`. الخادم يكتشف عدد الـ GPUs ويستخدمها تلقائيًا.
- **الاستكمال:** يحفظ Checkpoint كل `save_steps`. عند الاستكمال يُختار آخر Checkpoint **مكتمل**، وأي Checkpoint نصف مكتوب يُتجاهل. حالة المحسّن والجدولة ومولّد الأرقام العشوائية كلها تُستعاد.
- **الإيقاف الآمن:** ملف `STOP` يجعل التدريب يحفظ Checkpoint ثم يتوقف.

## 5. حماية البيانات

1. كتابة ذرّية لكل السجلات (ملف مؤقت ثم `fsync` ثم `rename`).
2. نسخة من سجل الداتاسيت قبل كل تعديل (`registry_history/`).
3. `backup` ينشئ أرشيف tar مع `MANIFEST.json` فيه SHA-256 لكل ملف، و`restore` يتحقق من كل ملف قبل الاستعادة.
4. الاستعادة لا تحذف شيئًا: الحالة الحالية تُنقل إلى `pre-restore-…/`.
5. `backup --hub user/repo` يرفع النسخة لمستودع Hugging Face خاص كنسخة خارج الجهاز.
